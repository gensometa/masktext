# masktext — 機密情報をオフラインでマスキング

Linux / macOSで使える単体コマンドです。処理時の外部送信やテレメトリはなく、
実行環境にPythonやNode.jsは必要ありません。ライセンスはMITです。

## 使い方

```sh
# 同じ階層に app.masked.log を作成。元ファイルは変更しない
masktext -f app.log

# 出力先を指定
masktext -f app.log -o sanitized.log

# テキストを直接渡す（以下は架空のデータ）
masktext -t '連絡先: alice@example.com'
# 連絡先: [REDACTED_EMAIL]

# パイプ入力 → 標準出力
cat app.log | masktext

# ファイル入力 → 標準出力
masktext -f app.log -o -

# 検出だけ行う。検出ありなら終了コード1、内容は出力しない
masktext --check -f app.log --stats
```

`-f/--file`、`-t/--text`、`-o/--output`を使用できます。位置引数1つも
テキストとして扱いますが、ファイルとの混同を避けるため明示指定を推奨します。
位置引数を使う場合はオプションを先に指定してください。

ファイル入力は拡張子の前に`.masked`を付けます。拡張子がなければ末尾に追加します。
既存ファイルは標準で上書きせず、`--force`で明示的に許可します。
元ファイルを出力先にすることは禁止し、ハードリンクやシンボリックリンク経由でも
保護します。出力先の親フォルダは事前に作成してください。
出力ファイルの権限は所有者だけが読み書きできる`0600`です。
一時ファイルへの書き込みが完了してから保存先を確定します。

終了コードは成功が`0`、`--check`で検出ありが`1`、入力などのエラーが`2`です。
`--stats`は検出値を含まない件数のJSONを標準エラー出力に書きます。
重複する検出はまとめるため、件数は置換箇所の数になります。

## インストール

[公開リポジトリ](https://github.com/gensometa/masktext)のリリースをワンライナーで導入できます。

```sh
curl -fsSL https://raw.githubusercontent.com/gensometa/masktext/v0.1.0/install.sh | sh -s -- gensometa/masktext v0.1.0
```

Linux/macOSのamd64/arm64を自動判定し、SHA-256を照合して`~/.local/bin`に
インストールします。`sudo`は不要です。`curl`・`tar`・`sha256sum`または`shasum`が
必要です。必要に応じて`export PATH="$HOME/.local/bin:$PATH"`をシェル設定に追加してください。
既存のmasktextコマンドは置き換えます。更新は新しいタグで同じ操作を行います。
削除する場合はインストールしたバイナリを削除してください。

現時点では作業フォルダで次のコマンドを使えます（Go 1.23以降が必要）。

```sh
go build -trimpath -o masktext ./cmd/masktext
./masktext --help
```

## 検出範囲と注意点

標準ではメールアドレス、IPv4/IPv6、一般的なキー名に続くパスワード・APIキー等、
一部のGitHub/AWS/OpenAI形式/Slackトークン、JWT形式、Bearer認証、PEM秘密鍵、
URL内の認証情報、Luhnチェックを通る13〜19桁のカード番号形式を置換します。
電話番号はIDとの誤判定があるため`--phone`で有効にします。

任意の秘密を完全に検出することはできません。氏名・住所・生年月日・個人番号・
社内固有情報は自動検出の対象にしていません。独自ルールと共有前の目視確認が必要です。
既知の接頭辞やキー名を伴わない秘密、エンコード済みの値、特殊な設定形式などは
見逃す可能性があります。マスキングしても流出済みの認証情報は失効しないため、
漏れた認証情報は別途無効化・再発行してください。

UTF-8テキスト専用、1回32 MiBまでです。改行コードと非検出部分は保持します。
不正なUTF-8やNULを含む入力は出力せずエラーにします。Shift_JISなどは事前変換が必要です。
PDF・Office・画像・圧縮ファイル・フォルダ一括処理には対応していません。
全文をメモリに読み込みます。

テキストとして置換するため、結果が有効なJSON/YAML等になる保証はありません。
重複検出は秘密の一部が残らないよう広い範囲でまとめます。たとえばURL認証情報と
メール形式の検出が重なると、ホスト名も置換する場合があります。
マスキング後も`password`などのキーは残るため、再検査で検出されることがあります。

実際の秘密を`-t`で渡すとシェル履歴やプロセス一覧に残る可能性があります。
実データはファイルまたは標準入力で渡してください。独自ルールのファイルにも
実名などが入るため、公開リポジトリに含めないでください。

## 独自ルール

```json
{
  "rules": [
    { "name": "PERSON", "literal": "山田太郎" },
    { "name": "EMPLOYEE_ID", "pattern": "EMP-[0-9]{6}" }
  ]
}
```

```sh
masktext -f notes.txt --config rules.json
```

完全一致文字列またはGo/RE2形式の正規表現を追加できます。
ルール名は大文字英字で始まる英大文字・数字・アンダースコアの40文字以内です。
正規表現のマッチ全体を置換します。先読み・後読み・後方参照は使用できません。
